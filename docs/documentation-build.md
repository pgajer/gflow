# Documentation sources and builds

- Edit roxygen in `R/`; `make document` regenerates Rd, NAMESPACE, and native bindings.
- Edit README.md directly. Its figure is generated by `tools/render_basin_showcase.R`;
  after installing a matching build, use `make showcase` to reproduce it.
- Edit the four `vignettes/*.Rmd` sources and shared `vignettes/guide.css`.
  `make build` includes self-contained HTML guides in the source archive.
- `tools/check_installed_guides.R` checks actual installed help and vignette discovery,
  then runs the introductory workflow from a temporary working directory.
- `_pkgdown.yml`, `pkgdown/extra/extra.css`, and `tools/build_website.R` build a
  website from these same sources. The task-organized reference index comes from
  the maintained API catalog. Core entry-point examples execute on the site;
  specialized/archive examples retain their source and may require extra inputs.

For an installed package built from the current sources:

```sh
Rscript -e 'install.packages("pkgdown", repos="https://cloud.r-project.org")'
make website R_ENV="env -u R_HOME"
```

The builder verifies that the installed code manifest matches the checkout.
Output is `build/site/`; it is generated and excluded from package archives and
Git. `docs/` holds these maintained notes, not generated pages. The site is
explicitly labeled unreleased, matching NEWS and the current distribution.

The GitHub Pages workflow builds from a clean checkout and publishes this output.
The same clean build checks installed documentation before publishing. Scientific
and private reports stay in their established manuscript/private locations.
